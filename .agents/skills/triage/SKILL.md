# Triage

Evaluate incoming issues on GitHub (`fderuiter/imednet-toolkit`) using live labels from `docs/agents/triage-labels.md` and commands from `docs/agents/issue-tracker.md` (`docs/agents/triage-labels.md` overrides stale label strings in frozen `.rst` docs and `.github/ISSUE_TEMPLATE/*.yml`).

Unless an explicit PR number `#<n>` is requested (`gh pr view` / `gh pr diff`), triage focuses on issues. Every comment posted to GitHub during triage **must** start with:

```markdown
> *This was generated by AI during triage.*
```

## Reference Docs

- [AGENT-BRIEF.md](AGENT-BRIEF.md): structure and durability rules for `ready-for-agent` briefs
- `docs/agents/triage-labels.md`: live GitHub label mapping & `.rst`/template overrides
- `docs/agents/issue-tracker.md`: `gh` CLI queries and issue conventions

## Live Labels & Categories

Apply exact live labels from `docs/agents/triage-labels.md` (and verified `area:*` / `priority:*` dimensions):

- **Categories:** `type:bug`, `type:enhancement`, `type:feature`, `type:refactor`, `type:docs`, `type:tech-debt`, `type:ci`, `type:test`, `type:security`, `type:epic`, `type:research`
- **Triage States:**
  - `status:triage` — maintainer evaluation in progress
  - `question` — waiting on reporter clarification (pair with concrete questions in a comment)
  - `ready-for-agent` + `status:ready` — fully scoped with attached agent brief, ready for agent execution
  - `status:needs-design` (or `status:ready` + `help wanted` without `ready-for-agent`) — requires human design decision or manual execution
  - `wontfix` (or `duplicate` / `invalid`) — closed with durable rejection rationale directly inside the GitHub closing comment (no local rejection files)

If state labels conflict (e.g., both `status:ready` and `wontfix`), flag and confirm with the maintainer before modifying.

## Workflows

### 1. Show What Needs Attention
Query GitHub issues (`gh issue list --state open --json number,title,labels,comments,updatedAt`) and group oldest-first into:
1. **Unlabeled**: missing `status:*` / `type:*` labels
2. **`status:triage`**: evaluation in progress
3. **`question` with recent reporter comments**: ready to re-evaluate

Show counts and a one-line summary per item; let the maintainer choose which issue to triage.

### 2. Triage a Specific Issue (`#42`)
1. **Gather context:** Read full issue details (`gh issue view <n> --comments`), explore relevant code using `CONTEXT.md` vocabulary and `docs/adr/` decisions, and run two checks:
   - **Redundancy:** search existing `packages/` code by domain concept to detect if already implemented.
   - **Prior rejection (`wontfix` memory):** search closed `wontfix` GitHub issues (`gh issue list --state closed --label wontfix --json number,title,body,comments`) for matching rejected concepts before re-debating.
2. **Recommend:** State recommended `type:*`, `area:*`, `priority:*`, and state label with concise codebase findings. Wait for maintainer direction.
3. **Verify claim:** Reproduce bugs deterministically (or verify requested behavior/PR tests) and report confirmed path, failed repro, or missing detail (`question`).
4. **Grill (if design detail is missing):** Activate `grilling` and `domain-modeling` to sharpen domain terms (`CONTEXT.md` / `docs/adr/`) a round at a time.
5. **Apply outcome & normalize title (`<type>(<area>): <outcome>` if needed):**
   - **Agent-ready:** Apply `ready-for-agent` + `status:ready` and post structured brief per [AGENT-BRIEF.md](AGENT-BRIEF.md).
   - **Human-required:** Apply `status:needs-design` (or `status:ready` + `help wanted`), noting human blockers.
   - **Waiting on reporter:** Apply `question` and post a `## Triage Notes` comment summarizing what is established and concrete numbered questions.
   - **Close (`wontfix` / `duplicate` / `invalid`):** Close via `gh issue close` with explanation (pointing to code if already implemented, or writing full durable architectural/scope rationale in the closing comment so future `wontfix` searches recover it).

## Quick State Override

When the maintainer explicitly specifies the target state (e.g., `"move #42 to ready-for-agent"`), confirm label/comment actions concisely, apply the live labels from `docs/agents/triage-labels.md`, and check whether an agent brief should be posted.
