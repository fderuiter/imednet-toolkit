# Domain Docs (`CONTEXT.md` & `docs/adr/`)

How agent skills consume and update domain terminology and architectural decisions in `imednet-toolkit`.

## Before Exploring, Read These

- **`CONTEXT.md`** at the repository root (single-context domain glossary for `iMednet EDC`).
- **`docs/adr/`**: architectural decision records (`0001-*.md`, `0002-*.md`, ...) in the area you are touching. Do **not** re-litigate accepted ADRs unless explicit evidence justifies reopening one.

If `CONTEXT.md` lacks a domain concept needed for a new workflow or model, resolve terms incrementally via the `domain-modeling` skill rather than inventing unapproved synonyms.

## ADR Publishing Rules (`scripts/build_docs.py`)

When creating or modifying an ADR under `docs/adr/`:

1. Name the file sequentially: `docs/adr/NNNN-<kebab-slug>.md` (matching `^\d{4}-.+\.md$`).
2. Start the file with a single H1 heading: `# <Title>` (required by Sphinx/MyST and `docs/adr/index.rst` generation).
3. Regenerate `docs/adr/index.rst` before finishing by running `hatch run docs` (or `python scripts/build_docs.py` in the workspace environment so `generate_adr_index()` stays synchronized).
4. Never introduce unlisted dependencies or contradict `docs/explanation/architecture.rst` without an explicit ADR note (`> _Contradicts ADR-NNNN (<topic>), worth reopening because…_`).

## Using Glossary Vocabulary

Keep `CONTEXT.md` free of implementation details (pure glossary only). Whenever naming public classes, tests, CLI commands, or issues for domain concepts (`Study`, `Subject`, `Site`, `Form`, `Record`, `Visit`, `Interval`, `Variable`, `Query`, `Data Dictionary`, `Job`), use canonical `CONTEXT.md` terms over listed `_Avoid_` synonyms.
